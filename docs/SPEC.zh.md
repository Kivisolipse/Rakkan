# Rakkan 规范 v0.2

[English](SPEC.md) · **中文**

> 每个字都有落款 · Every character, signed.

Rakkan（落款）用纯文本标出一篇 Markdown 里哪些字是人写的、哪些是 AI 写的、哪些是从别处引来的，精确到每个字符。本文是语法规范；Obsidian 插件只是它的一种实现。

本文所有示例都是虚构的。

> **拿不准时，不算人写。** 没标记的字算人写的（原则 2），所以凡是没标成功的，默认都落到人头上。因此，写入或改动标记的实现，在拿不准是谁写的时，只能往"不算人写"的方向错：保留原样、算给模型，或者报出来。一个字只有原来就是人写的、或者是人刚打的，才能算人写的。

## 1. 原则

1. **纯文本优先**：没有插件，文件照样读得懂；几条正则就能复现区分效果。
2. **人类默认**：没标记的字都算人写的。标记的义务在 AI 那边。
3. **简洁、能手写**：和 `**`、`~~` 是一个家族。
4. **样式可自定义**：默认按模型家族上色，每个家族、每个模型都能单独换样式。
5. **不锁定**：能和 iA 的 Markdown Annotations 互相转换。
6. **精确到每个字符**：哪怕只有一个字属于另一位作者，也要能标出来。
7. **职责边界**：会让署名悄悄丢失或认错的问题，实现要提醒；单纯的显示问题不管。

## 2. 速览

```
人写的字不用标。&&这句是 AI 写的&&[@gpt]，然后又回到人。
书上说「纸短情长」[@fakebook]，我深以为然。

&& Claude (claude-opus-5-5)

整段 AI，里面可以有标题、列表、表格、代码块。
中间插一句 @@这是作者自己补的@@，再引一句模型说出自 mies 的 "less is more"[@mies]。

&&

> 整段的引用用引用块，最后一行注明出处。
> [@fakebook]
```

| 写法 | 含义 |
|---|---|
| `&&字&&` | 行内 AI 文字 |
| `@@字@@` | 人写的字，在 AI 区域和带出处的引用里用（原创岛） |
| 一行 `&& 署名`（最短 `&& AI`） | AI 块开始 |
| 单独一行 `&&` | AI 块结束，只当结束 |
| `「字」[@key]`、`"字"[@key]` | 引用：`[@key]` 是人写的，引号里的字归 key 指的作者；是模型写的，字仍算模型的（§4.4） |
| `&&字&&[@key]` | 行内 AI 文字注明是哪个模型 |
| `\&&`、`\@@` | 转义 |

## 3. 标记

一行在 CR LF、CR 或 LF 处结束，和 CommonMark 一样。实现按原样读入行尾，写回时也不改：不会把一篇笔记的行尾统一成一种。

### 3.1 标记长度

正文里的标记是**恰好两个**相同字符：`&&` 或 `@@`。`&&&`、`@@@` 或更长的连写按原样显示。单个 `&`、`@`（邮箱、@某人）不算。

前面紧挨着奇数个反斜杠的连写是转义：`\&&` 显示为 `&&`，不是标记。反斜杠先两两成对，与 CommonMark 相同：`\\` 是一个字面的反斜杠，所以 `\\&&` 显示一个反斜杠，`&&` 仍是标记；`\\\&&` 显示为 `\&&`。

`&&` 后面紧跟 HTML 实体（`&&amp;`）时，实体优先，这两个 `&` 不算标记。

### 3.2 区域和上下文

一篇文章由三种区域组成：

- **人的区域**：默认。这里 `&&` 生效，`@@` 原样显示。
- **AI 区域**：AI 块，和行内 `&&…&&`。这里 `@@` 生效，`&&` 原样显示。
- **带出处的引用**，即 `[@key]` 是人写的引用（§4.4）：`&&` 和 `@@` 都生效，用来标出引用时改动的字。模型写的引用属于它所在的 AI 区域。

嵌套只有一层：

| 外层 | 生效的标记 | 内层 |
|---|---|---|
| 人的区域 | `&&` | 行内 AI |
| 行内 AI | `@@` | 原创岛 |
| AI 块 | `@@` | 原创岛 |
| 引用 | `&&`、`@@` | 行内 AI（里面还可以有 `@@`）、原创岛 |
| 原创岛 | 无 | — |

### 3.3 配对

- 行内标记不跨行。
- 同一行里，同种标记从左到右两两配对，不看两边是什么字（不继承 CommonMark 的 flanking 规则，`说&&「我」&&是` 照样生效）。
- 没闭合的标记按原样显示。
- 两种标记交叉时（`&&甲@@乙&&丙@@`），后开的那一对按原样显示：这里 `&&甲@@乙&&` 是行内 AI，其中的 `@@` 原样显示。

### 3.4 AI 块

```
&& Claude (claude-opus-5-5)

块里的内容

&&
```

- **开头**：一行以 `&&` 开头，后面跟空白和署名。署名里不能出现 `&&`，所以 `&& 一句话 &&` 是行内，不是块。转义与正文相同（§3.1）：`&& 甲 \&& 乙 (id)` 开一个块，署名为 `甲 && 乙`。`&&一句话`（没有空白）也不是块的开头。
- **结尾**：单独一行 `&&`。它**只当结尾**。
- 块不嵌套。块里又遇到一个开头，就当上一块漏了结尾：上一块在这里结束，实现应提醒。
- 没有开头的单独 `&&` 按原样显示，实现应提醒。
- 开头一直没等到结尾（到文件末尾），这个开头按原样显示，实现应提醒。
- 开头、结尾所在的行前后**必须空一行**。不空行，紧跟在表格下面的 `&&` 会被当成表格的一行。例外：紧贴 frontmatter 的开头，上面不用空行，下面仍要空一行。实现应提醒并能自动补空行。
- 开头、结尾行最多缩进 3 个空格；在引用块、列表里不算。

### 3.5 署名

块署名写成 `显示名 (标识)`，两部分可以省一个，不能都省：

| 署名 | 显示名 | 标识 |
|---|---|---|
| `&& Claude (claude-opus-5-5)` | Claude | claude-opus-5-5 |
| `&& (gpt-5)` | （按标识显示家族名 GPT） | gpt-5 |
| `&& AI` | AI | — |
| `&& 助手（claude-sonnet-5-5）` | 助手 | claude-sonnet-5-5 |

- AI 的标识是模型 ID，照官方 API 的写法。
- 全角括号也认。
- 标识不用尖括号：Markdown 会把 `<claude-opus-5-5>` 当成 HTML 标签吞掉。
- 整篇的作者继续用 frontmatter 的 `author`。

### 3.6 模型家族

家族从模型 ID 的前缀认，认不出时看显示名：

| 前缀 | 家族 |
|---|---|
| `claude` | Claude |
| `gpt`、`chatgpt`、`o1`、`o3`、`o4` | GPT |
| `gemini` | Gemini |
| `deepseek` | DeepSeek |
| `grok` | Grok |
| `llama` | Llama |
| `muse` | Muse |
| `qwen` | Qwen |
| `mistral`、`mixtral` | Mistral |
| `kimi`、`moonshot` | Kimi |
| `glm` | GLM |

`muse` 后面只能是结尾、`-` 或数字：`muse-spark-1.3` 是 Muse，`museum` 不是。

## 4. 引用和作者

### 4.1 `[@key]`

写法照 Pandoc 的引用语法。key 是一串不含空白和方括号的字符。

`[@key]` **紧跟在收尾符号后面**（中间最多一个空格）才算注明作者：

- 收尾引号 `」` `』` `”` `"`：引号里的字引自 key。这些字算谁的，看 `[@key]` 是谁写的（§4.4）。往回找配对的开引号，只在同一行里找；`"` 不分左右，找同一行最近的那个。单引号不支持（和撇号分不开）。
- 行内标记的结束符：`&&字&&[@key]` 注明这段 AI 文字的模型；`@@字@@[@key]` 注明这段人写的字是谁写的。

跟在别的字后面的 `[@key]` 是普通的 Pandoc 引用，不改变归属。后面紧跟 `(` 或 `:` 的不算（那是链接或链接定义）。

引号本身归外层；`[@key]` 是标记。

### 4.2 引用块

整段的引用用引用块，**最后一行**只写 `[@key]`：

```
> 第一行引用
> 第二行引用
> [@fakebook]
```

整个引用块里的字都归 key，块里 `&&` `@@` 都生效。在 AI 块里则是模型的声明（§4.4）。

### 4.3 署名簿与补充定义

`[@key]` 指向的作者，一行定义一个：

```
- @key: 名字 (标识) · 种类 · #颜色
```

| 部分 | 写法 |
|---|---|
| 名字 | 显示名，和块署名一样可以省，也可以只写标识 |
| 标识 | 圆括号里：模型 ID、网址、ISBN……全角括号也认 |
| 种类 | `人`、`AI`、`来源`（也认 `human`、`ai`、`source`）。不写时，标识认得出模型家族就是 AI，否则是人 |
| 颜色 | `#rrggbb` 或 `#rgb`，可以不写 |
| 分隔 | `·`（也认 `•`、`\|`）；名字之后的部分顺序随意，每一项都可以省 |

key 是从 `@` 到第一个空白之间的全部字符，去掉末尾的一个冒号。key 里可以有冒号，与 Pandoc 相同：`@doe:2006: Jane Doe · 来源` 定义的是 `doe:2006`。不按最后一个 `: ` 切分，所以 `@doe: 回复: 一封信` 定义的是 `doe`。

行首的 `- ` 可以省。种类的含义：`人` 有自己的颜色，没写颜色时由 key 算出一个固定的颜色；`AI` 用模型家族的颜色；`来源` 给不知道作者的出处（书、网页），调暗显示。

**署名簿**是库里的一篇笔记，每个作者一行，其余内容（标题、说明）一律忽略；同一个 key 以第一次出现为准。署名簿同时是参考文献表。

单篇文件**末尾**也可以写同样的定义，文件单独发出去时也带着；和署名簿冲突时以文件自己的为准：

```
@opus: Claude (claude-opus-5-5) · AI
@fakebook: 《一本不存在的书》 · 来源
```

定义不加方括号：`[@key]: …` 是 Markdown 的链接定义，会整行消失。key 找不到定义，照样算有出处的引用，只是没有专属颜色。

### 4.4 引文是一种声明

引文是一种声明：写下 `[@key]` 的人，声明这些字出自 key。**人写的声明直接算数，模型写的声明要有证据。**所以看的是 `[@key]` 是谁写的：

- **在人写的文字里**（包括原创岛）：是人的声明，引号里的字归 key。在 AI 块里手打的引文（`@@「…」[@x]@@`），人给模型的一句话补上的引号和 `[@x]`，都算这一种。
- **在模型写的文字里**（行内 AI、AI 块，包括 AI 块里带出处的引用块）：是模型的声明。引号里的字仍算模型的，和这段 AI 文字的其他地方一样，`&&` 原样显示，`@@` 标原创岛。声明保留下来：实现记下它的范围和 key，给 lint 和网关核对用。`[@key]` 仍是标记。

```
我引一句「纸短情长」[@fakebook]。          ← 人的声明：字归 fakebook
&&常有人说「少即是多」[@mies]。&&          ← 模型的声明：字算模型的
```

给模型的修改签名的实现由此而来：模型加的引文、改了字的引文，都成为模型的文字，也就是模型的声明；不会凭模型的一句话变成人写的或出处的。

**待办：已核对的声明。** 带证据的模型声明以后可以升级，字归 key。证据计划有三种来源，这一轮都不实现：

1. 引用工具（比如 MCP 的一个 quote 工具）自己读原文、确认这些字是原文的子串，再由它写入引文和 `[@key]`。
2. 引文链接到库里的原文（块引用、剪藏快照），由 lint 逐字比对。
3. 人在插件里手动确认。

已核对的声明怎么写，还没定。

## 5. 跳过的地方

以下地方的 `&&` `@@` 都不是标记：

| 地方 | 说明 |
|---|---|
| frontmatter | 文件开头 `---` 到下一个 `---` |
| 代码块 | 围栏照 CommonMark 配对：至少 3 个 `` ` `` 或 `~`，结束围栏同种字符、不短于开头；可以缩进在列表里或待在引用块里 |
| 行内代码 | 反引号按个数配对，只在同一行里配 |
| 公式 | `$$…$$` 块；行内 `$…$` 照 Pandoc 规则：开头的 `$` 后面不能是空白，结尾的 `$` 前面不能是空白、后面不能紧跟数字；`\$` 是转义 |
| Obsidian 注释 | `%%…%%`，可以跨行 |
| 链接网址 | `[文字](网址)` 的网址部分、裸网址 `https://…` |
| iA 标注块 | 文件末尾 `---` 后紧跟 `Annotations:` 的部分 |

**裸网址**照 GFM 延伸到下一个空白，末尾的句读（`.,;:!?`）不算网址。末尾起作用的标记也同样不算网址，而是结束外面的那一段：`&&见 https://example.com/&&` 里网址是 `https://example.com/`，`&&` 结束行内 AI，后面带不带 `[@key]` 都一样。在那里什么也不结束的连写仍属于网址：会开始一段的（如 `https://example.com/&& 后文&&`），以及 `\&&`、`&&&`。

跳过的地方不改变归属：AI 块里的代码整段算 AI，`&&$x^2$&&` 整条公式算 AI。

**没闭合的代码围栏**会让后面整篇都变成代码，所有标记悄悄失效，实现应提醒。

**公式里夹着 `&&` 或 `@@`** 很可能是金额被当成了公式，实现应提醒，建议写成 `\$`。

## 6. 代码里的归属

代码块默认不解析任何标记。要在代码内部精确到字，在 info string 里**声明**启用的标记：

````
```ts @@
let total = 0
let count = @@0@@
```
````

- 声明是语言名后面只由 `@` 或只由 `&` 组成、至少两个字符的词。两种可以一起声明：```` ```ts @@ &&& ````。
- 声明写几个，块里就只有恰好这么长的连写算标记。代码里本来有 `&&`，就声明 `&&&`：

  ````
  ```c &&&
  if (a && b) return &&&fallback()&&&;
  ```
  ````

- 上下文规则和正文一样：AI 块里的代码声明 `@@` 标原创岛；人的区域里的代码声明 `&&&` 标 AI。
- 去标记时，按声明写一条正则即可。

## 7. 统计

原创、AI 生成、引用的字数按 Unicode 码位数，不算空白、标记、frontmatter、注释、补充定义、iA 标注块、代码围栏行、引用块的 `>` 前缀，以及行语法。

**空白**指带 Unicode 属性 White_Space 的所有字符（包括不换行空格、U+2028、U+0085）。带 Default_Ignorable_Code_Point 属性的字符（BOM、零宽空格和连接符、变体选择符、软连字符）也不计数：看不见的字不算"写了"。

**行语法**指渲染后不显示为文字的 Markdown：标题、列表项、任务、脚注开头的引导符（`## `、`- `、`1. `、`- [x] `、`[^1]: `），以及以 `|` 开头的行里的竖线，分隔行（`|---|:-:|`）则整行都算。行语法不归任何人。

**已知局限**：任务的勾选框是行语法，所以记不下是谁勾的、谁取消的。给修订签名的实现要把模型勾选或取消勾选的任务报出来。

## 8. 读原文的程序

标记会把词隔开，按原文搜索时搜不到。宽松搜索在每两个字之间插一个「空隙」：

```
[@&*=~`\[\]]*
```

比如「分页机制」写成 `` 分[@&*=~`\[\]]*页[@&*=~`\[\]]*机[@&*=~`\[\]]*制 ``。空隙只用字符类，不用嵌套量词，保证线性时间。

## 9. 不采用的写法

- 整篇默认作者（frontmatter 让整篇算 AI）
- 零宽字符藏标记
- 按字符位置记在文件末尾、用哈希校验
- `++字++` 当引用标记
- `&&[opus]…&&`、`[&opus]: …`
